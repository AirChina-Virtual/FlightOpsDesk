# VamSys.Infrastructure — 连接服务器与保存本地数据

这个项目负责和 vaMSYS 通信，并把工作区、草稿和任务进度保存到本机。它还会检查重复记录，在请求超时或程序中断后判断服务器是否已经完成操作。项目使用 net10.0，依赖 Core、Microsoft.Data.Sqlite 和 Windows 的密钥保护组件。

程序使用的 Operations API 文档副本放在 docs/contracts/operations.json，编译时会以 Operations.OpenApi.json 的名称打包进去。Pilot API 文档仅供参考，目前没有接入。

## 哪些文件负责连接和提交

| 文件 | 具体作用 |
|---|---|
| OperationsTransport.cs | 发送请求、管理登录令牌、控制请求频率，并处理服务器要求等待、报错和取消 |
| OperationsAdapter.cs | 把修改转换成 API 请求，读取返回数据，检查记录是否正确以及修改是否成功 |
| OperationsQueries.cs | 按页读取数据，查找可能与准备新增的记录重复的内容 |
| CandidateIndex.cs | 按 ID、名称或注册号等信息快速查找记录；同名的不同记录都保留 |
| OperationsBatchExecutor.cs | 逐条提交修改，保存每一步的进度；中断后先核对结果，再更新本地数据 |
| DemoService.cs | 提供带有演示标记的测试数据；连接真实服务器失败时不会偷偷切换到演示 |
| Performance.cs | 记录发送了多少请求，以及等待、保存和处理分别用了多久 |

有些记录需要先创建，再补充其他属性。创建返回 ID 后，必须先把 ID 和进度保存成功，才能提交下一步。如果上次停在“执行中”或“结果未知”，恢复时只查询结果，不直接重发新增或修改请求。账号或权限出错时任务暂停；其他记录失败也不能让一条结果未确认的记录失去防重复保护。

识别机场时同时检查 ICAO 和 IATA 代码；比较航线起降机场时，使用当前航空公司在服务器上的机场 ID。机场代码查找使用 OperationsAdapter 内的索引：代码、远端 ID、ICAO、IATA 都映射到远端 ID 集合，只有恰好对应 1 个机场时才能使用。索引在已读机场、机场快照列表或当前航空公司变化时自动重建。判断快照是否变化时，依据列表对象、行数和最后一行，因此修改快照时只能替换列表，或者删除、追加行，不能直接改已有行的内容。

航线和航路新建前，按远端起降机场 ID 查询候选。同一次执行中，每个机场对只查询一次：只有全部分页读完，结果才会缓存；如果第一页就发现重复，会立即停止，不缓存不完整的结果。本批确认成功的新建、修改和删除，会用确认后的版本替换缓存中的旧版本，改变了起降机场的旧版本也会移除。结果未知的写入仍由原有的预留机制保护。缓存只在一次执行内有效，恢复任务时重新读取。

完整刷新时，读取飞机会直接使用本次已读到的机型，不再重复请求机型列表。刷新数据先在新的集合中合并，保存成功后才替换当前工作区；不会深拷贝全部任务和撤销历史。用于查重的数据必须全部读取成功后才能使用，并在确认修改成功后更新。如果一个机场是否创建成功还不清楚，就先暂停后续机场创建，避免换一种机场代码又创建一次。

## 哪些文件负责保存数据

| 文件 | 具体作用 |
|---|---|
| WorkspaceStore.cs | 提供读取工作区、任务、语言设置和连接密钥的入口 |
| WorkspaceStore.Schema.cs | 定义数据库格式；升级前备份，检查版本，并确保升级全部完成或全部撤回 |
| WorkspaceStore.Persistence.cs | 处理完整保存和单步进度保存，防止较旧的数据覆盖较新的结果 |
| WorkspaceStore.Resources.cs | 保存字段定义、原始数据、草稿和撤销／重做历史 |
| WorkspaceStore.History.cs | 捕获、提交和确认 v4 历史差异，读取并验证栈与步骤 |
| DataDirectoryLease.cs | 防止两个程序同时操作同一个数据目录 |
| ../../tests/TestSupport | 仅供测试／QA 构建：存储故障注入和测试程序集的内部访问授权 |

v4 把工作区设置、任务、数据行、历史栈和每个历史步骤分开保存。确认一条服务器修改成功时，只保存这条记录和相关信息，不重新处理无关数据。

正式程序集不包含 `Barrier` 故障注入属性或测试友元授权。存储边界使用可消除的 partial 方法，正式构建时连同调用参数一起移除；测试项目通过 `VamSysTestSupport=true` 链接 tests/TestSupport 中的实现，仍然检查同一份业务代码。测试构建输出到 artifacts/test-build，和正式程序集隔离。在线任务的性能统计与演示模式属于产品功能，继续保留。

编辑表格单元格后的自动保存使用 `TrySaveDraftRowsAsync`：只更新目标草稿行、变化步骤和必要的历史栈顺序。任务、其他数据行、字段列表和冲突都不写。它和完整保存一样检查版本号，任何一行更新数量不等于 1 都会整体撤回。内存中找不到被编辑的行时返回 false，由调用方改用完整保存。新增、删除、导入、撤销、刷新等其他操作仍使用完整保存。

保存前冻结行 JSON 与历史载荷；成功只确认该次捕获。连续编辑同一单元格时仍更新原步骤 After，不能因为没有新增步骤而漏存历史。淘汰最旧步骤或新建分支时删除对应步骤，保留的步骤不重写。旧整块格式、v2、v3 直接事务迁移到 v4，每一步撤销／重做及当前位置全部保留。

任务显示成功、更新本地数据、清理对应撤销记录等变化，必须作为一次完整保存一起成功或一起失败。保存失败时，不能先把界面改成成功，也不能继续向服务器提交下一条。

## 升级数据库时如何保护数据

旧数据库升级前，先用 SQLite 自带的备份功能保存一份完整副本，包括已经保存到数据库日志中的内容。所有升级步骤成功后才更新版本号。发现损坏数据、重复编号，或数据库版本比程序支持的更新时，停止处理，不擅自改写数据。

连接密钥继续使用 Windows 当前用户的加密机制保护。升级前的备份只记录当时的状态：之后如果已经修改过服务器，就不能直接换回旧备份继续任务，否则可能重复执行已经完成的操作。

## 已经测试什么，还有什么不能确定

Tests 使用模拟服务器和单独的测试数据库，检查分批读取、请求限速、冲突、超时、ID 保存失败及程序被中断后的恢复。这些测试不能代替真实航空公司账号测试；文档没有说明清楚的更换机型、清空关联等操作仍然禁用。
