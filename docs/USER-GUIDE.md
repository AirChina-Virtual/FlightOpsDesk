# FlightOps Desk 使用指南

FlightOps Desk 通过 vaMSYS 的 Operations API，批量管理虚拟航空公司的机场、机型、飞机、航路和航线。基本流程如下：

**连接航空公司 → 读取最新数据 → 在“数据管理”中修改 → 在“变更审阅”中核对并提交 → 在“任务中心”查看结果**

## 安装与启动

解压 Windows 11 x64 程序包，运行目录中的 `FlightOpsDesk.exe`。程序包已包含所需运行库，请保留整个目录（DLL、Assets、PRI 和 XBF 文件）。升级时先关闭旧版，再把新版解压到单独的目录；旧数据会在升级前自动备份，详见 [升级与恢复说明](STORAGE-MIGRATION.md)。

没有 API 账号时，可以在“工作区”页创建演示工作区，或者离线导入、导出 CSV。演示操作不会修改真实数据。

## 连接航空公司

1. 新建工作区。每个工作区对应服务器上的一家虚拟航空公司，不能改作另一家公司的工作区使用。
2. 在“连接与设置”填写 Orwell 配置的 Operations Client ID 和 Secret，保存后测试连接。服务器地址固定为官方地址。
3. 重启程序后，缓存和草稿都会恢复，但需要重新测试连接；程序不会自动提交。

测试连接时，程序从机队或机场数据识别所属 VA；新建、还没有机队和机场的 VA，会改从等级（ranks）或载具（containers）数据识别。都读不到时提示先连接，不会猜测。

两个保存入口都会去掉 Client ID 首尾的空格，但不会裁剪 Secret：

- **保存连接设置**：Secret 留空时，保留原来的值。
- **仅更新 API 凭据**：必须填写新的 Secret。凭据失效导致任务暂停时使用这个入口。它不会应用同一页上未保存的其他设置，也不会改变目标 VA 或任务。更新后重新连接，核验原 VA，再恢复任务。

保存失败时，凭据和工作区都不会只更新一部分。凭据使用当前 Windows 用户的 DPAPI 加密。完全没有机型或机场可用来识别 VA 时，请先在 Orwell 建立基础记录。

## 读取数据

点击“从 API 刷新”读取五类资源；飞机通过机型列表逐个获取。所有数据都读取、合并并保存成功后，才会替换当前数据和查找信息；中途失败或取消时，保留原来的数据。

刷新时，程序会比较上次读取的原始数据、你正在编辑的草稿和服务器最新数据：

- 双方修改的是不同字段时，自动合并。
- 改了同一个字段时，在“审阅冲突”中选择保留哪一方。
- 服务器已删除、但本地仍有修改的记录，不会自动重建。
- 只有 `updated_at` 改变时，更新元数据并保留草稿；它不是可靠的业务版本号。待修改的同一业务字段远端有变化时仍进入冲突处理。

刷新后，原有数据对应的撤销历史会被清除。

## 编辑数据

数据管理页显示当前资源的全部记录，默认每页 200 条，可选 100／200／500 条。

- **编辑单元格**：单元格平时显示文字。点击单元格、用 Tab 进入，或在选中的单元格上按 Enter／F2 后出现输入框，输入内容会立即写入草稿。在选中但未编辑的单元格上直接打字，会用输入的内容替换原值。已删除的行显示为浅色只读文字。
- **按类型输入**：是／否字段（如 Is Hidden）点击或按空格切换；航线类型、机型类型从列表中选；机场代码输入时提示本工作区的机场；标签提示已用过的标签；日期旁有日历按钮，选日期时保留原来的时刻；星期列表可以勾选，也有“每天”“工作日”“清除”；整数字段只接受数字。时间、日期、星期输入完后会自动整理格式，例如 `930` 变为 `09:30`，`2026/3/1` 变为 `2026-03-01 00:00:00`，`mon,fri` 变为 `monday,friday`；读不懂的内容保持原样。
- **当场提示**：有问题的单元格显示红框，鼠标悬停显示原因（必填、格式不对、引用的机场或机型不存在等），改正后提示消失。服务器上已有的记录，改过的单元格底部显示强调色，悬停显示服务器上的值。只读单元格悬停说明原因。跨行的检查（重复主键、可能重复的新建）仍在“校验”和审阅时进行。
- **键盘**：Enter／Shift+Enter 保存并移到下一行／上一行同一列；Tab／Shift+Tab 移到右边／左边并直接编辑，行尾接到下一行；方向键在单元格之间移动；Esc 放弃这次编辑，恢复编辑前的值，不留撤销步骤；Delete 清空非必填单元格。
- **复制与粘贴**：Ctrl+C 复制当前单元格。Ctrl+V 粘贴一个值到当前单元格；从 Excel 等复制的多行多列内容，从当前单元格开始向右、向下填入本页，先确认改动数量，只读和超出本页的单元格不变，整块一次撤销。
- **向下填充**：先用复选框选中要填的记录，再在某个单元格上按 Ctrl+D，把它的值填到已选记录的同一列，确认后执行，一次撤销。
- **记录详情**：在单元格上按 Ctrl+Enter，或在“批量操作”菜单、右键菜单里点“记录详情”，右侧显示这条记录的全部字段，带 * 的是必填项。在这里修改和在表格里修改是同一份草稿，可以撤销。
- **复制为新记录**：选中记录后在“批量操作”菜单点“复制为新记录”，复制出的记录主键为空，补全后再提交。
- **自动保存**：停止输入 700 毫秒后自动保存，只写入被编辑的行。意外终止时，最后一次尚未保存的输入可能丢失。
- **撤销／重做**：工具栏的两个箭头按钮或 Ctrl+Z／Ctrl+Y。一次编辑（从打开输入框到离开这个单元格）算一步。撤销或重做只改动已有行时，只保存这些行；当前搜索结果和排序保持不变，下次查询时再重新计算。新增、删除行的撤销会完整保存，并重新查询。
- **资源与工具栏**：页面标题旁的标签切换机场、机型、飞机、航路、航线，有待提交改动的资源在标签上显示数量。工具栏第二行依次是“新增”（下拉可从 CSV 导入）、“批量操作”（选中记录后可用，显示已选数量）、“数据”（从 API 刷新、解决冲突、校验）、撤销、重做；右侧“审阅并提交”显示待提交数量。
- **搜索、筛选与排序**：作用于当前资源的全部记录，改完自动生效（搜索在停止输入后生效，按 Enter 立即生效）。筛选为“全部／已修改／标记删除”三个选项，“已修改”显示数量。排序在“排序”菜单里选列和升序／降序，也可以点列头：第一次升序，再点降序，第三次取消。修改搜索词或筛选后，回到第一页并清空选择；只更换排序时保留选择。
- **视图**：“视图”菜单切换舒适／紧凑密度，以及隐藏或显示列（状态列和主键列始终显示）。隐藏的列只在本次运行内记住；批量规则和记录详情仍可使用全部列。
- **右键菜单**：在行上右键（或按 Shift+F10）可以复制单元格、把改过的单元格还原为服务器上的值、打开记录详情、复制为新记录、分配机型、删除或取消删除。右键一行不在选择内时，会只选中这一行。- **分页**：可用首页、上一页、下一页、末页或输入页码跳转。更换每页条数时，保留原来首条记录所在的位置。
- **密度**：舒适（行高 40 DIP）或紧凑（32 DIP），默认舒适，在“视图”菜单里切换。设置对所有工作区生效，重启后保留。切换时保留分页、选择和首条可见记录。
- **查询期间**：表格变暗并暂停编辑和批量操作，上一批结果保留；可以点击取消，取消后继续使用原来的结果。

单格编辑只更新该行的状态，结果不会立即跳动；下次查询时按最新内容重新计算。
## 批量操作

页脚“选择”菜单提供：选择本页、选择全部筛选结果、清空选择。翻页会保留其他页的选择，底部同时显示已选总数和当前页已选数。

批量规则、分配机型、删除、恢复和到期停用只处理已选记录；没有适用的选择时，这些按钮会被禁用，也不会自动扩展到筛选结果。如果要处理全部结果，请先明确选择全部筛选结果。

- 编辑、机型分配和停用会跳过已删除的行；恢复只处理已删除的行。
- 预览显示已选、跳过、未变化和实际变化的数量。没有实际变化的记录不新增撤销步骤。
- 预览期间锁定数据、选择和工作区；取消不会应用任何修改。

## 导入与导出 CSV

在线工作区导入 CSV 后，先生成待检查的修改，不会直接覆盖从服务器读取的原始数据；已有 ID 的记录需要先刷新核对。CSV 表头和 API 字段名可能不同，程序会按文档转换。不认识的 CSV 列会保留，但不会发给 API。

审阅页按资源提供“导出机场 CSV”“导出航线 CSV”等入口，每次只导出对应的资源，只包含变化的记录，并保留未知列。文件超过 10 MB 时会拆分。导出完成后，任务标为“待到 Orwell 导入”，这不表示 API 提交成功。

## 审阅与提交

飞机的“货物容量（kg）”与机队的“最大货物容量（kg）”只按 kg 解释。例如 `2205` 就是 `2205 kg`，不会按 lbs 换算或自动取整。CSV 仍用 `Freight`、`Max Freight` 列名；离线导入可以保留小数，在线审阅会要求修正为非负整数。可选空值保持省略或继承，不自动变成零；请求不附带 `weight_unit` 或 SimBrief 对象。

新在线机队在“航司参数”单元格选择一个已批准、未受限的参数。连接或刷新会尝试读取参数，也可在设置页点击“读取航司参数”。它只用于校验和新机队关联，没有参数增删改页面，旧 CSV 的 `Allowed Prefix IDs` 不会自动当成参数 ID。已有机队不支持在线改绑或解绑。

scheduled 航线可通过机队选择器预览替换、追加、移除。最终集合必须非空；提交前重新读取航线、核对字段冲突，并检查每个机队是否获准使用呼号和班号前缀。除 jumpseat 外，所有带机队的航线类型（scheduled、cargo、charter、training、vfr、repositioning）都做这项检查，并一次列出所有未获准的机队。审阅页对因此受阻的航线提供“移除未获准的 N 个机队”；提交后被服务器以同样原因拒绝（HTTP 422）的航线，任务中心提供“移除未获准的机队并重新审阅”。两者都是一次可撤销的草稿编辑，移除后航线仍须至少有一个机队。连接并读过航司参数后，数据页的 Fleet IDs 单元格也会标出未获准的机队。参数权限不足只阻止依赖此校验的操作。已按独立真实 A→AB→B→A 证据开放该范围，仍使用独立能力键。

飞机可以通过机队选择器修改 Fleet ID，在审阅中单独提交跨机队移动；不要在同一项中混改其他字段。目标机队必须属于当前 VA、可读取且未标记删除。程序从原机队核对飞机，再使用 PATCH 移动，并从目标机队路径读回核对；未知结果只读恢复，不重发 PATCH。

在导航中打开“变更审阅”。程序会先显示“正在整理审阅清单…”，在后台整理整个工作区，期间暂停编辑和导航。整理完成后：

- 按资源分组，显示目标 VA 和每条记录的字段差异。
- 明确区分本次提交、暂缓和受阻的项。
- 五类资源中已有独立真实请求和回读证据的字段范围已开放，审阅会注明依据；未覆盖变体仍保留原有样本与兼容限制。完整范围见源码文档的能力验证矩阵。
- 依赖的创建操作不在本次清单中时，相关修改会暂缓。

点击提交后，程序会在后台重新检查清单。内容或提交条件有变化时，会刷新清单并要求重新审阅；没有变化时，再显示确认框。最终确认、任务和页面使用同一份清单。删除操作需要另行确认。

确认后，程序先保存任务，再切换到任务中心并启动本次任务。取消确认或保存失败时不会启动。若工作区、运行模式或操作锁变化而无法启动，会明确提示，已保存的任务保留在任务中心。重新打开程序、连接或解除操作锁不会自动启动以前的 Pending 任务；旧任务须经人工核对后明确继续。

存在待执行或结果未知的任务时，不能刷新；审阅中涉及这些任务里同一记录（同一行、远端 ID 或代码／名称）的修改受阻，其他修改照常提交。冲突和逐行校验问题也只挡对应的修改，依赖它们的修改暂缓；审阅页上方仍列出这些问题。

审阅页每类资源标题旁有勾选框，默认全选。取消勾选后，这类资源本次不提交；其他资源中依赖这类资源新建记录的修改也一并不提交，确认框会说明数量。确认框按资源和操作汇总，并显示预计请求次数和耗时（每秒最多 1 次请求，限流等待和重试另计），可点“查看全部 N 项”查看明细。

在线任务完成后，如果工作区还有它刚核对通过的同类修改（之前因“每类操作先提交 3 条样本”而暂缓），任务卡片会显示“继续提交剩余 N 项”，点击进入审阅页继续。

## 任务、恢复与删除

在任务中心查看逐条结果和诊断信息。取消只会停止后续请求，不会撤销服务器上已完成的修改。恢复任务时只核对结果未知的写入，不会自动重发；已经成功的记录不会重复提交。

- 提交前的查询临时失败时，记录仍为“待执行”，可以稍后重试。写入被限流（HTTP 429）或被认证拒绝（HTTP 401／403）时，服务器没有处理该请求，记录同样回到“待执行”；认证失败还会暂停任务，更新凭据后继续。
- 请求还没发出就中断时（等待限流、刷新令牌失败或点了取消），记录回到“待执行”。程序在发送前先把步骤保存为“发送中”，所以重启后能区分“从未发出”和“可能已发出”：前者照常执行，后者只读核对。
- 修改请求可能已经发出、但无法查明服务器结果时，标记为“结果未知”，需要先核对再继续。写入请求最多等 90 秒，读取 30 秒。
- 写入后回读与提交内容不一致时，程序等 5 秒再读一次，第二次仍不一致才标为“结果未知”；两次读取都保留在诊断信息里。
- 每轮结束时，程序会对本轮新出现的“结果未知”项各只读核对一次，能确定的当轮完成，不用再点“继续”。核对读取失败时保持原状态和原因。不会重发任何写入。
- 新建请求没有收到回执时，程序查找提交后新出现、内容与本次新建一致、创建时间在请求期间内的记录（按服务器时钟校正，允许 60 秒误差）。恰好一条时自动绑定，并照常回读核对；找到多条时在“核对未知结果”中列出，预填第一条供核对。
- 机场或航线的删除请求没有收到回执，但之后读取该记录返回 404 时，程序把它标为“已删除（无回执）”。这是根据读取得出的结论，与 204＋404 的完整证据分开记录，也不计为已验证的操作。
- 在“核对未知结果”中，同一情况的项有 2 项以上时，先一次列出这一组，可选“全部确认”“逐条处理”或取消：删除收到 204 但仍可读、删除无回执且读到 404、删除无回执且与修改前一致、服务器接受了写入但值不同（逐行显示差异）、写入结果未知（全部只读核对，能证明未生效的标为失败）。需要读取的组会先逐项只读 GET 一次；不会重发任何写入。
- 500 会显示错误 ID（服务端提供时）并保持 Unknown，程序不会自动重发。
- 没有返回 ID 的创建，可以在“核对未知结果”中输入在 Orwell 找到的候选 ID。核对失败后可以重新打开并更正，候选历史会保留。匹配成功才会绑定远端 ID；服务器已确认的 ID 不能更换。
- 认为一次 Unknown 写入并未生效时，可在“核对未知结果”中选择“API 核对未生效”。它只发 GET：新建项须查不到符合判重条件的记录；修改或硬删除项读回的当前值须仍与修改前一致。通过后该项标为“失败”，本地草稿保留，需要时在审阅页重新提交；不通过则保持 Unknown。服务端若延后处理请求，读回旧值也可能只是暂时的，重新提交前建议先在 Orwell 确认。已被服务器接受的写入、已创建的记录，以及机场和航线的软删除不提供此选项。
- 旧版本留下的“先创建、再补字段”两步新建：如果创建已应答、补字段请求从未发出，继续任务时会先核对已创建记录仍与创建内容一致，再只补发剩余步骤，不会重复创建；补字段请求可能已发出时仍只读核对。

任务卡片提供“导出诊断”，导出脱敏 JSON 与 SHA-256 文件。包括完整字段错误、HTTP 状态、阶段、请求／服务器时间、追踪头和预期／实际字段差异。界面摘要可以缩短；正文超过 1 MiB 会明确标记截断，哈希对应完整的脱敏正文。OAuth、Token、Secret、Authorization 和 Cookie 不进入诊断包。

已有 jumpseat 的呼号、班号可能显示“服务端未保留”，仍可读取和保存；这两个字段暂不支持在线修改。新建仍要填写合法值，回读仅允许服务端将这两个字段返回为显式 null，其他字段严格核对。判重按机场对、类型、时刻与有效日期，不靠空班号。无 ID 恢复额外要求候选不属于提交前记录、创建时间位于已保存的请求窗口（允许 60 秒时钟偏差）且持久字段一致；旧任务缺少这些证据时继续保持 Unknown。

机场和航线使用“软删除”。本版对机场、scheduled 和 jumpseat 航线开放自动核对：原 DELETE 返回 204、步骤回执和身份匹配，随后同 ID 的详情 GET 为 404 时，显示“API 已核对不可见”并计入 API 核对成功；这不表示物理删除。GET 200、缺回执或读取失败时继续保留待处理状态。机型、飞机和航路仍按既有永久删除规则核对。删除前会检查本地引用并刷新依赖，但服务器仍可能拒绝。

任务中心增加“API 只读核对删除”，可对 Unknown 或已人工确认的软删除项补充核对，只发 GET；同任务内的 Pending 项不会执行。具备完整证据时会更新为 API 核对成功，并保留原人工确认来源；不具备时保留原状态。界面分别显示 API 核对、人工确认和未知数量。旧任务不会因升级或重连自动核对或重发。人工确认仍可使用，并在保存成功后才更新本地状态。

## 目前支持到什么程度

- 重量单位为 kg，日期和时刻为 UTC。分钟格式的表格保留 API 原始的秒数，日期保留原始的小数秒。
- PUT 只发送变化的字段。机场 Container IDs 清空时使用文档明确的 `[]`；其他未确认的清空操作禁用。
- 以下操作禁用：空航线机队集合、jumpseat 集合修改；跨 Jumpseat 类型的转换；既有机队参数改绑；未验证单位和复杂对象写入。
- 航线和航路的起降机场不能在线修改；到期停用是一次独立的 End Date 修改，需要满足日期关系校验。
- 新建航线的呼号和班号对所有类型都必填，包括 jumpseat；已有 jumpseat 的服务端空值允许保留。成本指数只能为空、AUTO 或 0–999 的整数。
- SimBrief 等复杂对象保存在原始 JSON 中，目前不提供编辑器。
- 所有 VA 合计每分钟最多 60 次请求，遵守 Retry-After。列表每页请求 100 条，读取 3,000 条航线约需 30 次请求；服务器拒绝该页长时，自动改用默认的 15 条。

## 本地数据与语言

- 在设置页可以即时切换简体中文和英文，不会重建页面或重发任务。官方字段、用户数据、CSV 和 API 内容不翻译。语言偏好对全部工作区生效。软件名称在两种语言中都是 **FlightOps Desk**。
- 数据库默认位于 `%LOCALAPPDATA%/VamSysBatch/workspaces.db`。可以在“连接与设置 → 数据存放位置”更改；设置了 `VAMSYS_DATA_DIR` 时以环境变量为准，设置页不能更改。同一个数据目录只允许运行一个程序实例。
- 更改位置时，程序先保存，把数据库和备份复制到新位置并校验，成功后切换并自动重启。校验不通过时位置不变。原位置的数据库改名为 `workspaces-moved-时间.db` 保留，不会删除，也不会再被打开；确认新位置正常后可以自行删除。
- 选中的文件夹如果已有其他文件，数据会放进其中的 `FlightOpsDesk` 子文件夹。选中的位置已有数据库时，只切换不复制，那份数据可能较旧，继续远端任务前要先核对。不能使用网络位置；也不要使用网盘同步文件夹。
- 启动时找不到所选位置（例如移动硬盘没有接上），程序不会新建空数据库，而是让你重试或改用默认位置。

快捷键（数据页）：`Ctrl+F` 搜索，`F5` 重新查询，`Ctrl+Z` 撤销，`Ctrl+Y` 重做。焦点在文本框内时，撤销和重做只作用于该文本框。搜索、筛选和排序改动后自动生效。
- 关闭窗口时先冻结编辑，再保存；保存失败时窗口保持打开，草稿保留。
- 程序没有远端事务回滚、删除恢复、团队服务器或自动同步。

首次打开旧版数据库时，会先保存完整备份，再升级到 v4，并完整保留原有的撤销、重做步骤和当前位置。升级要么全部完成，要么保留原数据。升级后如果已经发生远端写入，不能再用升级前的备份继续任务。

设置页的“先备份，再清理当前工作区”会显示工作区名称、数据目录及快照、草稿、任务、冲突和历史计数。确认后冻结操作并等待保存；存在 Running、Unknown、InFlight 或创建后尚未完成核对的记录时，先阻止清理。

程序先使用 SQLite 备份整个本地数据库，保存完整性检查结果、SHA-256 和清单到同一数据目录的 `Backups`。备份成功且版本没有变化后，才在一个事务里清除当前工作区的数据、历史、任务和验证标记。工作区名称、VA 绑定、连接和时刻设置、凭据密文以及其他工作区保留。成功后退出当前连接，需要重新连接和刷新。备份或事务失败不会清理。备份含其他工作区及加密凭据，按本地私有数据保管；本版不提供恢复备份后继续旧远端任务的快捷操作。

## 大量数据和问题排查

新增航线和航路前，先按机场 ID 查找可能重复的记录。机场、机型和飞机的数据全部读取后，会建立快速查找表；确认新增、修改或删除成功后，这个表会同步更新。检查飞机注册号是否重复时，会检查所有机型。

修改结果不确定时，查重会同时考虑修改前后的名称；删除结果不确定时，原记录仍视为可能存在。机场创建尚未核对成功时，后续的机场创建会显示“待执行”及原因，其他独立资源继续执行。

每次在线任务结束时，程序会尝试把请求量、限流等待、保存统计，以及各项结束时的状态和原因代码（按资源和操作计数，不含字段值和 ID）写入数据目录的 `performance/<工作区ID>/<任务ID>/<执行ID>.json`，其中不包含凭据或请求内容。参见 [性能报告与复现方式](PERFORMANCE.md)。
