# FlightOps Desk 使用指南

FlightOps Desk 通过 vaMSYS 的 Operations API，批量管理虚拟航空公司的机场、机型、飞机、航路和航线。基本流程如下：

**连接航空公司 → 读取最新数据 → 在“数据管理”中修改 → 在“变更审阅”中核对并提交 → 在“任务中心”查看结果**

## 安装与启动

解压 Windows 11 x64 程序包，运行目录中的 `FlightOpsDesk.exe`。程序包已包含所需运行库，请保留整个目录（DLL、Assets、PRI 和 XBF 文件）。升级时先关闭旧版，再把新版解压到单独的目录；旧数据会在升级前自动备份，详见 [升级与恢复说明](STORAGE-MIGRATION.md)。

没有 API 账号时，可以在“工作区”页创建演示工作区，或者离线导入、导出 CSV。演示操作不会修改真实数据。

## 连接航空公司

1. 新建工作区。每个工作区对应服务器上的一家虚拟航空公司，不能改作另一家公司的工作区使用。
2. 在“连接与设置”填写 Orwell 配置的 Operations Client ID 和 Secret，保存后测试连接。服务器地址固定为官方地址。
3. 重启程序后，缓存和草稿都会恢复，但需要重新测试连接；程序不会自动提交。

两个保存入口都会去掉 Client ID 首尾的空格，但不会裁剪 Secret：

- **保存连接设置**：Secret 留空时，保留原来的值。
- **仅更新 API 凭据**：必须填写新的 Secret。凭据失效导致任务暂停时使用这个入口。它不会应用同一页上未保存的其他设置，也不会改变目标 VA 或任务。更新后重新连接，核验原 VA，再恢复任务。

保存失败时，凭据和工作区都不会只更新一部分。凭据使用当前 Windows 用户的 DPAPI 加密。完全没有机型或机场可用来识别 VA 时，请先在 Orwell 建立基础记录。

## 读取数据

点击“从 API 刷新”读取五类资源；飞机通过机型列表逐个获取。所有数据都读取、合并并保存成功后，才会替换当前数据和查找信息；中途失败或取消时，保留原来的数据。

刷新时，程序会比较上次读取的原始数据、你正在编辑的草稿和服务器最新数据：

- 双方修改的是不同字段时，自动合并。
- 改了同一个字段时，在“审阅冲突”中选择保留哪一方。
- 服务器已删除、但本地仍有修改的记录，不会自动重建。

刷新后，原有数据对应的撤销历史会被清除。

## 编辑数据

数据管理页显示当前资源的全部记录，默认每页 200 条，可选 100／200／500 条。

- **编辑单元格**：单元格平时显示文字。点击单元格或用 Tab 进入后出现输入框，输入内容会立即写入草稿。按 Enter 或 Esc 关闭输入框，焦点留在该单元格；Tab 移到下一列。已删除的行显示为浅色只读文字。
- **自动保存**：停止输入 700 毫秒后自动保存，只写入被编辑的行。意外终止时，最后一次尚未保存的输入可能丢失。
- **撤销／重做**：在命令栏的“更多”菜单中。撤销或重做只改动已有行时，只保存这些行；当前搜索结果和排序保持不变，下次应用查询时再重新计算。新增、删除行的撤销会完整保存，并重新查询。
- **搜索、筛选与排序**：作用于当前资源的全部记录。在搜索框按 Enter 或点击“筛选／排序”应用条件；输入了但还没应用的条件会显示“条件未应用”。修改搜索词或筛选类型并应用后，回到第一页并清空选择；只更换排序时保留选择。
- **分页**：可用首页、上一页、下一页、末页或输入页码跳转。更换每页条数时，保留原来首条记录所在的位置。
- **密度**：舒适（行高 40 DIP）或紧凑（32 DIP），默认舒适。设置对所有工作区生效，重启后保留。切换时保留分页、选择和首条可见记录。
- **查询期间**：表格变暗并暂停编辑和批量操作，上一批结果保留；可以点击取消，取消后继续使用原来的结果。

单格编辑只更新该行的状态，结果不会立即跳动；再次点击“筛选／排序”会按最新内容重新计算。

## 批量操作

页脚“选择”菜单提供：选择本页、选择全部筛选结果、清空选择。翻页会保留其他页的选择，底部同时显示已选总数和当前页已选数。

批量规则、分配机型、删除、恢复和到期停用只处理已选记录；没有适用的选择时，这些按钮会被禁用，也不会自动扩展到筛选结果。如果要处理全部结果，请先明确选择全部筛选结果。

- 编辑、机型分配和停用会跳过已删除的行；恢复只处理已删除的行。
- 预览显示已选、跳过、未变化和实际变化的数量。没有实际变化的记录不新增撤销步骤。
- 预览期间锁定数据、选择和工作区；取消不会应用任何修改。

## 导入与导出 CSV

在线工作区导入 CSV 后，先生成待检查的修改，不会直接覆盖从服务器读取的原始数据；已有 ID 的记录需要先刷新核对。CSV 表头和 API 字段名可能不同，程序会按文档转换。不认识的 CSV 列会保留，但不会发给 API。

审阅页按资源提供“导出机场 CSV”“导出航线 CSV”等入口，每次只导出对应的资源，只包含变化的记录，并保留未知列。文件超过 10 MB 时会拆分。导出完成后，任务标为“待到 Orwell 导入”，这不表示 API 提交成功。

## 审阅与提交

在导航中打开“变更审阅”。程序会先显示“正在整理审阅清单…”，在后台整理整个工作区，期间暂停编辑和导航。整理完成后：

- 按资源分组，显示目标 VA 和每条记录的字段差异。
- 明确区分本次提交、暂缓和受阻的项。
- 未在当前工作区回读验证过的操作，每次最多提交 3 条样本，其余保留为草稿。
- 依赖的创建操作不在本次清单中时，相关修改会暂缓。

点击提交后，程序会在后台重新检查清单。内容或提交条件有变化时，会刷新清单并要求重新审阅；没有变化时，再显示确认框。最终确认、任务和页面使用同一份清单。删除操作需要另行确认。

存在待执行或结果未知的任务时，不允许新的提交和刷新，避免重复修改。

## 任务、恢复与删除

在任务中心查看逐条结果和诊断信息。取消只会停止后续请求，不会撤销服务器上已完成的修改。恢复任务时只核对结果未知的写入，不会自动重发；已经成功的记录不会重复提交。

- 提交前的查询临时失败时，记录仍为“待执行”，可以稍后重试。写入被限流（HTTP 429）时，服务器没有处理该请求，记录同样回到“待执行”。
- 修改请求可能已经发出、但无法查明服务器结果时，标记为“结果未知”，需要先核对再继续。
- 没有返回 ID 的创建，可以在“核对未知结果”中输入在 Orwell 找到的候选 ID。核对失败后可以重新打开并更正，候选历史会保留。匹配成功才会绑定远端 ID；服务器已确认的 ID 不能更换。

机场和航线使用“软删除”：收到 204 只能说明请求被接收，之后查询返回 404 也不能直接当作删除成功。因此，机场和航线的删除任务结束时总会显示“需处理”，这是预期行为。在 Orwell 核对后，可以明确记录为“人工确认”；这不算 API 自动验证成功。机型、飞机和航路是永久删除。删除前会检查本地引用并刷新依赖，但服务器仍可能拒绝。

## 目前支持到什么程度

- 重量单位为 kg，日期和时刻为 UTC。分钟格式的表格保留 API 原始的秒数，日期保留原始的小数秒。
- PUT 只发送变化的字段。机场 Container IDs 清空时使用文档明确的 `[]`；其他未确认的清空操作禁用。
- 以下操作禁用：飞机更换机型；已有航线的 Fleet IDs 替换、追加、移除和清空；跨 Jumpseat 类型的转换。
- 航线和航路的起降机场不能在线修改；到期停用是一次独立的 End Date 修改，需要满足日期关系校验。
- 航线的呼号和班号对所有类型都必填，包括 jumpseat；成本指数只能为空、AUTO 或 0–999 的整数。
- SimBrief 等复杂对象保存在原始 JSON 中，目前不提供编辑器。
- 所有 VA 合计每分钟最多 60 次请求，遵守 Retry-After。列表每页请求 100 条，读取 3,000 条航线约需 30 次请求；服务器拒绝该页长时，自动改用默认的 15 条。

## 本地数据与语言

- 在设置页可以即时切换简体中文和英文，不会重建页面或重发任务。官方字段、用户数据、CSV 和 API 内容不翻译。语言偏好对全部工作区生效。软件名称在两种语言中都是 **FlightOps Desk**。
- 数据库默认位于 `%LOCALAPPDATA%/VamSysBatch/workspaces.db`，可以通过 `VAMSYS_DATA_DIR` 指定其他目录。同一个数据目录只允许运行一个程序实例。
- 关闭窗口时先冻结编辑，再保存；保存失败时窗口保持打开，草稿保留。
- 程序没有远端事务回滚、删除恢复、团队服务器或自动同步。

首次打开旧版数据库时，会先保存完整备份，再升级到 v4，并完整保留原有的撤销、重做步骤和当前位置。升级要么全部完成，要么保留原数据。升级后如果已经发生远端写入，不能再用升级前的备份继续任务。

## 大量数据和问题排查

新增航线和航路前，先按机场 ID 查找可能重复的记录。机场、机型和飞机的数据全部读取后，会建立快速查找表；确认新增、修改或删除成功后，这个表会同步更新。检查飞机注册号是否重复时，会检查所有机型。

修改结果不确定时，查重会同时考虑修改前后的名称；删除结果不确定时，原记录仍视为可能存在。机场创建尚未核对成功时，后续的机场创建会显示“待执行”及原因，其他独立资源继续执行。

每次在线任务结束时，程序会尝试把请求量、限流等待和保存统计写入数据目录的 `performance/<工作区ID>/<任务ID>/<执行ID>.json`，其中不包含凭据或请求内容。参见 [性能报告与复现方式](PERFORMANCE.md)。
