# FlightOps Desk 使用指南

FlightOps Desk 通过 vAMSYS 的 Operations API，批量管理虚拟航空公司的机场、机型、飞机、航路和航线。一次完整的操作是：

**连接航空公司 → 读取最新数据 → 在“数据管理”中修改 → 在“变更审阅”中核对并提交 → 在“任务中心”查看结果**

几条贯穿全程的原则：

- **写入只发一次**：程序不会自动重发。结果不明时，只发读取请求去核对。
- **写后必核对**：每次写入后都读回核对，通过才算成功。
- **只改需要改的**：修改请求只发送变化的字段。
- **问题只挡相关修改**：一处有问题，只挡住与它相关的修改，其他修改照常提交。

## 安装与升级

解压 Windows 11 x64 程序包，运行目录中的 `FlightOpsDesk.exe`。程序包已带齐运行库，请保留整个目录（DLL、Assets、PRI、XBF 文件）。

升级时先关闭旧版，再把新版解压到单独的目录。首次打开旧版数据库时，程序会先完整备份，再升级。升级要么全部完成，要么保留原数据。详见 [升级与恢复说明](STORAGE-MIGRATION.md)。

没有 API 账号时，可以在“工作区”页创建演示工作区，或者离线导入、导出 CSV。演示操作不会修改真实数据。

打开程序或在标题栏切换工作区时，程序在后台读取工作区，页面上显示读取进度；读完之前不能编辑、切换页面或再换工作区，也不会自动保存。切换时会先保存当前工作区。读取失败时留在原来的工作区并提示原因。读取期间关闭窗口，程序会在读取完成后再保存并关闭。

## 连接航空公司

1. **新建工作区**：每个工作区对应服务器上的一家虚拟航空公司（VA），不能改作另一家公司使用。
2. **填写凭据**：在“连接与设置”中填写 Orwell 里配置的 Operations Client ID 和 Secret，保存后测试连接。服务器地址固定为官方地址。
3. **识别所属 VA**：测试连接时，程序从机队或机场数据识别所属 VA；新建的 VA 还没有机队和机场时，改从等级或载具数据识别。都读不到时会提示，不会猜测。完全没有可用来识别的记录时，请先在 Orwell 建立基础记录。

保存凭据有两个入口，都会去掉 Client ID 首尾的空格，Secret 保持原样：

- **保存连接设置**：Secret 留空时保留原来的值。
- **仅更新 API 凭据**：必须填写新的 Secret。凭据失效导致任务暂停时用这个入口。它不会应用同一页上未保存的其他设置，也不改变目标 VA 或任务；更新后重新连接，核对原 VA，再继续任务。

凭据用当前 Windows 用户的 DPAPI 加密。保存失败时，凭据和工作区都不会只更新一部分。重启程序后，缓存和草稿都会恢复，但要重新测试连接；程序不会自动提交任何东西。

## 读取数据

**整体刷新**：点“从 API 刷新”，读取全部五类资源，其中飞机按机型逐个读取。

**只刷新一类资源**：用“数据”菜单里的“只刷新当前资源”。它只读取这一类资源及其引用的资源：航线连同机场和机型，航路连同机场，飞机连同机型。其他资源的数据、草稿、冲突和快照时间都不变。

刷新有这些规则：

- **读完才替换**：所有数据都读取、合并并保存成功后，才替换当前数据；中途失败或取消时，保留原来的数据。
- **失败后续读**：失败后 5 分钟内在同一连接中再刷新，已完整读到的资源不再重读，只读剩下的。期间提交过改动，或者超过了 5 分钟，就全部重读。
- **有任务未完成时不能刷新**：存在待执行或结果未知的在线任务时，不能刷新，也不能改连接设置。

刷新时，程序会比较三份数据：上次读取的原始数据、你的草稿、服务器的最新数据。

- 双方改的是不同字段时，自动合并。
- 改了同一个字段时，在“审阅冲突”中选择保留哪一方。
- 服务器已删除、本地仍有修改的记录，不会自动重建。
- 只有 `updated_at` 变化时，只更新元数据，保留草稿。

刷新后，原有数据的撤销历史会被清除。

## 编辑数据

### 表格

“数据管理”页显示当前资源的全部记录，默认每页 200 条，可选 100／200／500 条。

- **切换资源**：页面标题旁的标签用来切换机场、机型、飞机、航路、航线；有待提交改动的资源，标签上显示数量。
- **工具栏**：依次是“新增”（下拉可从 CSV 导入）、“批量操作”（选中记录后可用）、“数据”（刷新、只刷新当前资源、解决冲突、校验）、撤销、重做；右侧“审阅并提交”显示待提交的数量。
- **搜索、筛选和排序**：作用于全部记录，改完自动生效。搜索在停止输入后生效，按 Enter 立即生效。
  - 筛选有“全部／已修改／标记删除”三项。
  - 排序可以在“排序”菜单里选，也可以点列头：第一次升序，再点降序，第三次取消。
  - 改搜索词或筛选后回到第一页，并清空选择；只改排序时保留选择。
- **分页**：首页、上一页、下一页、末页，或输入页码跳转。更换每页条数时，保持原来首条记录的位置。
- **视图**：
  - **密度**：在“视图”菜单切换舒适（行高 40 DIP，默认）或紧凑（32 DIP）。
  - **隐藏列**：在“视图”菜单隐藏或显示列，状态列和主键列始终显示，已不存在的列名自动忽略。批量规则和记录详情仍能使用全部列。

  这两项设置对所有工作区生效，重启后保留。
- **查询期间**：表格变暗，暂停编辑和批量操作，上一批结果保留；可以点取消，取消后继续使用原来的结果。

### 编辑单元格

- **进入编辑**：点击单元格、用 Tab 进入，或在选中的单元格上按 Enter／F2，出现输入框，输入内容立即写入草稿。在选中但未编辑的单元格上直接打字，会用输入的内容替换原值。
- **按类型输入**：
  - 是／否字段（如 Is Hidden）点击或按空格切换。
  - 航线类型、机型类型从列表中选。
  - 机场代码输入时提示本工作区的机场；标签提示已用过的标签。
  - 日期旁有日历按钮，选日期时保留原来的时刻。
  - 星期可以勾选，也有“每天”“工作日”“清除”。
  - 整数字段只接受数字。
- **格式自动整理**：时间、日期、星期输入完会自动整理，例如：
  - `930` 变为 `09:30`；
  - `2026/3/1` 变为 `2026-03-01 00:00:00`；
  - `mon,fri` 变为 `monday,friday`。

  读不懂的内容保持原样。
- **当场提示**：
  - 有问题的单元格显示红框，鼠标停留时说明原因（必填、格式不对、引用的机场或机型不存在等），改正后提示消失。
  - 服务器上已有的记录，改过的单元格底部显示强调色，鼠标停留时显示服务器上的值。
  - 只读单元格，鼠标停留时说明原因。
  - 跨行的检查（重复主键、可能重复的新建）在“校验”和审阅时进行。
- **已删除的行**：显示为浅色只读文字。

### 键盘、复制与填充

- **Enter／Shift+Enter**：保存，并移到下一行／上一行的同一列。
- **Tab／Shift+Tab**：移到右边／左边并直接编辑，行尾接到下一行。
- **方向键**：在单元格之间移动。
- **Esc**：放弃这次编辑，恢复编辑前的值，不留撤销步骤。
- **Delete**：清空非必填的单元格。
- **复制与粘贴**：
  - Ctrl+C 复制当前单元格。
  - Ctrl+V 把一个值粘贴到当前单元格。
  - 从 Excel 等处复制的多行多列内容，从当前单元格开始向右、向下填入本页。程序先确认改动数量；只读单元格和超出本页的部分不变；整块算一步撤销。
- **向下填充**：先用复选框选中记录，在某个单元格上按 Ctrl+D，把它的值填到已选记录的同一列，确认后执行，算一步撤销。
- **数据页快捷键**：
  - Ctrl+F 搜索；
  - F5 重新查询；
  - Ctrl+Z 撤销、Ctrl+Y 重做（焦点在文本框里时，只作用于该文本框）；
  - Ctrl+Enter 打开记录详情；
  - Shift+F10 打开右键菜单。

### 记录详情、右键菜单、撤销与保存

- **记录详情**：在单元格上按 Ctrl+Enter，或从“批量操作”菜单、右键菜单打开。右侧显示这条记录的全部字段，带 * 的是必填项；在这里修改和在表格里修改是同一份草稿。
- **复制为新记录**：选中记录后，在“批量操作”菜单中选择；复制出的记录主键为空，补全后再提交。
- **右键菜单**：
  - 可以复制单元格、把改过的单元格还原为服务器上的值、打开记录详情、复制为新记录、分配机型、删除或取消删除。
  - 右键的那一行不在选择内时，会只选中这一行。
- **撤销与重做**：一次编辑（从打开输入框到离开这个单元格）算一步。
  - 只改动已有行时，只保存这些行，搜索结果和排序暂时不变，下次查询时再重新计算。
  - 新增、删除行的撤销会完整保存，并重新查询。
- **自动保存**：停止输入 700 毫秒后自动保存，只写入被编辑的行。意外终止时，最后一次还没保存的输入可能丢失。
- **关闭窗口**：先冻结编辑再保存；保存失败时窗口保持打开，草稿保留。

## 批量操作

页脚的“选择”菜单提供：选择本页、选择全部筛选结果、清空选择。翻页会保留其他页的选择，底部同时显示已选总数和本页已选数。

批量规则、分配机型、删除、恢复和到期停用都只处理已选记录：

- **不会自动扩大范围**：没有适用的选择时，这些按钮被禁用，也不会自动扩展到全部筛选结果。要处理全部结果，请先明确“选择全部筛选结果”。
- **跳过的行**：编辑、分配机型和停用会跳过已删除的行；恢复只处理已删除的行。
- **先预览**：预览显示已选、跳过、未变化和实际变化的数量。没有实际变化的记录不新增撤销步骤。
- **预览期间**：锁定数据、选择和工作区；取消不会应用任何修改。

## 导入与导出 CSV

- **导入**：在线工作区导入 CSV 后，先生成待审阅的修改，不直接覆盖从服务器读取的原始数据。已有 ID 的记录需要先刷新核对。CSV 表头与 API 字段名不同时，程序按文档转换；不认识的列会保留，但不会发给 API。
- **导出**：审阅页按资源提供“导出机场 CSV”“导出航线 CSV”等入口，只导出对应资源中有变化的记录，并保留未知列；文件超过 10 MB 时会拆分。导出后，任务标为“待到 Orwell 导入”，这不表示 API 提交成功。

## 审阅与提交

### 审阅页

在导航中打开“变更审阅”，程序会先在后台整理整个工作区，期间暂停编辑和导航。整理完成后：

- **按资源分组**，显示目标 VA 和每条记录的字段差异。
- **每条记录的第一行写明操作、ID 和记录内容**：
  - 机场：代码和名称；
  - 机型：名称和机型代码；
  - 飞机：注册号、名称和所属机型；
  - 航路：起降机场和航路串；
  - 航线：类型、呼号和班号（jumpseat 没有）、起降机场。

  删除显示被删记录的内容，新建显示新记录的内容。过长的值会截短，每条只占一行。
- **分清三种状态**：本次提交、暂缓、受阻。所依赖的新建不在本次清单中时，相关修改暂缓。
- **样本限制**：
  - 已有真实证据的字段和操作范围，审阅会注明依据，并照常提交。
  - 没有证据覆盖的，每类操作先只提交 3 条样本，其余暂缓；样本核对通过后，任务卡片会显示“继续提交剩余 N 项”。
- **按资源部分提交**：每类资源标题旁有勾选框，默认全选。取消勾选后，这类资源本次不提交；其他资源中依赖它新建记录的修改也一并不提交，确认框会说明数量。

### 提交

点击提交后，程序在后台重新检查清单：

- **有变化时**：内容或提交条件有变化，会刷新清单，要求重新审阅。
- **没变化时**：显示确认框，按资源和操作汇总，并显示预计的请求次数和耗时（每秒最多 1 次请求，限流等待另计），可以点“查看全部 N 项”看明细。
- **删除**：需要另外确认。

最终确认、任务和页面使用同一份清单。确认后，程序先保存任务，再切换到任务中心并启动任务。下列情况不会启动：

- 取消确认或保存失败时。
- 工作区、运行模式或操作锁有变化而无法启动时，程序会明确提示，已保存的任务留在任务中心。

重新打开程序、连接或解除操作锁，都不会自动启动以前的待执行任务。

### 哪些修改会被挡住

- **未完成任务里的同一记录**：存在待执行或结果未知的任务时，审阅中涉及这些任务里同一记录（同一行、远端 ID 或代码／名称）的修改受阻，其他修改照常提交。
- **冲突和逐行校验问题**：只挡住对应的修改，依赖它们的修改暂缓。审阅页上方会列出这些问题。
- **航线机队未获准使用前缀**：除 jumpseat 外，所有带机队的航线类型（scheduled、cargo、charter、training、vfr、repositioning）提交前都会检查：每个机队是否获准使用这条航线的呼号和班号前缀。程序一次列出所有未获准的机队，可以这样处理：
  - 审阅页对受阻的航线提供“移除未获准的 N 个机队”；
  - 提交后被服务器以同样原因拒绝（HTTP 422）的航线，任务中心提供“移除未获准的机队并重新审阅”。

  两者都是一次可撤销的草稿编辑，移除后航线仍须至少有一个机队。连接并读过航司参数后，数据页的 Fleet IDs 单元格也会标出未获准的机队：单元格加红框，鼠标停留时列出这些机队。读取参数的权限不足时，只挡住依赖这项检查的操作。

### 特定字段与操作

- **航线机队集合**：scheduled 航线可以用机队选择器预览替换、追加、移除，最终集合必须非空。提交前程序会重新读取航线并核对冲突。
- **航司参数**：新的在线机队要在“航司参数”单元格选择一个已批准、未受限的参数。连接或刷新时会尝试读取参数，也可以在设置页点“读取航司参数”。程序没有参数的增删改页面；已有机队不支持在线改绑或解绑；旧 CSV 的 `Allowed Prefix IDs` 不会自动当成参数 ID。
- **飞机跨机队移动**：用机队选择器修改 Fleet ID，在审阅中单独提交，同一项里不要混改其他字段。目标机队必须属于当前 VA、可读取，且没有标记删除。程序先从原机队核对飞机，再移动，然后从目标机队读回核对；结果不明时只读核对，不重发移动请求。
- **重量**：飞机的“货物容量（kg）”和机型的“最大货物容量（kg）”只按 kg 解释，例如 `2205` 就是 2205 kg，不换算、不取整。
  - CSV 仍用 `Freight`、`Max Freight` 列名。
  - 离线导入可以保留小数，在线审阅会要求改成非负整数。
  - 可选的空值保持为空，不自动变成 0。
- **jumpseat 航线**：
  - 已有 jumpseat 的呼号、班号可能显示“服务端未保留”，仍可读取和保存，但暂不支持在线修改这两个字段。
  - 新建时留空，程序会自动填入服务器接受的占位值。
  - 判重按机场对、类型、时刻和有效日期，不靠空班号。

## 任务中心

在任务中心查看每一项的结果和诊断信息。

- **取消**：只停止后续请求，不会撤销服务器上已完成的修改。
- **继续**：任务卡片上的“继续”先核对结果未知的写入，再执行剩下的项；已成功的记录不会重复提交。

### 请求没有成功时

- **提交前的查询临时失败**：记录仍为“待执行”，可以稍后再试。
- **服务器肯定没处理**：写入被限流（HTTP 429），或请求没能发出，说明服务器没有处理。程序先处理完本轮其他记录，按服务器要求的时间等待，再发一次；仍不成功才回到“待执行”。依赖它的记录（例如新机型下的飞机）随后一起提交。
- **认证被拒绝（HTTP 401／403）**：记录回到“待执行”，任务暂停；更新凭据后继续。
- **中断后**：程序在发送前先把步骤保存为“发送中”，所以重启后能分清“从未发出”和“可能已发出”：前者照常执行，后者只读核对。
- **结果未知**：写入可能已经发出，但查不清服务器的结果，就标为“结果未知”，要先核对才能继续。写入请求最多等 90 秒，读取最多等 30 秒。
- **HTTP 500**：显示服务器提供的错误 ID，保持“结果未知”，不会自动重发。

### 写入后的核对

- **读回核对**：写入后读回，与提交内容逐字段比较。不一致时，等 5 秒再读一次；第二次仍不一致才标为“结果未知”。两次读取都保留在诊断信息里。
- **服务器的改写**：服务器会改写部分字段再保存，例如：
  - 注册号、机型代码、呼号、班号、SELCAL、Hex Code 转成大写；
  - 名称和备注去掉首尾空格；
  - 星期名转成小写；
  - 空的备注存成空值。

  这些改写都经过真实取证登记，算作一致；核对通过后，草稿换成服务器保存的写法。没有登记的改写仍标为“结果未知”。
- **新建飞机的 Internal Remarks**：服务器不保存随新建请求一起发送的 Internal Remarks。填了这一列时，程序这样处理：
  1. 先新建飞机，拿到 ID；
  2. 再单独修改一次 Internal Remarks；
  3. 然后核对。

  第 2 步没完成时，任务显示“记录已创建，后续步骤尚未被服务器处理”。点“继续”会先核对已建的飞机，再补发这一步，不会重复新建。第 1 步的应答丢失时，第 2 步不会发出，处理方法见下文“处理结果未知”。

  2026-11-17 之前保存、还没完成的这类任务仍是一次新建请求（Internal Remarks 随新建发送），回读会因 Internal Remarks 为空而不一致：新建已应答的，可以用“接受服务器的值”处理；新建应答也丢失的，程序找不到匹配的记录，只能在 Orwell 核对。
- **本轮结束时自动核对**：每轮结束时，程序对本轮新出现的“结果未知”项各只读核对一次，能确定的当轮完成，不必再点“继续”。读取失败时保持原状态和原因。

### 处理结果未知

在“核对未知结果”中处理。同一情况有 2 项以上时，程序先列出这一组，可选“全部确认”“逐条处理”或取消；需要读取的组会先逐项只读一次。

- **新建没有收到回执**：程序查找提交后新出现、内容与这次新建一致、创建时间在请求期间内的记录（按服务器时钟校正，允许 60 秒误差）。
  - 恰好一条时自动绑定，再照常读回核对。
  - 找到多条时列出来，预填第一条供核对。
  - 也可以输入在 Orwell 里找到的 ID。匹配成功才绑定；核对失败后可以重新打开更正，候选历史会保留；服务器已确认的 ID 不能更换。
- **填了 Internal Remarks 的新建飞机没有收到回执**：Internal Remarks 要在新建后单独写入，没收到新建回执就不会写。查找和核对输入的 ID 时，只比较新建请求实际发出的值，其他条件同上。
  - 找到并绑定后，这一项仍是“结果未知”，提示记录已在服务器上建好、Internal Remarks 没有写入。程序不会补写：之后点“继续”、每轮结束时的核对、重新打开程序后，都只发读取请求。
  - 在“核对”中可以选择接受服务器的值：这一项标为人工确认（不计为 API 核对成功），快照换成服务器上的记录，没写进去的 Internal Remarks 作为冲突留在草稿中。处理冲突后，照常审阅并提交这次修改。
  - 这种项不提供“API 核对未生效”，因为记录确实已经建好。
- **服务器接受了写入但值不同**：逐行显示差异，可以选择接受服务器的值，不再写入。
- **认为写入并未生效**：选“API 核对未生效”。它只发读取请求：
  - 新建项要查不到符合判重条件的记录；
  - 修改项或永久删除项，读回的当前值要仍与修改前一致。

  通过后该项标为“失败”，草稿保留，需要时在审阅页重新提交；不通过则保持“结果未知”。服务器有时会延后处理请求，读回旧值也可能只是暂时的，重新提交前建议先在 Orwell 确认。已被服务器接受的写入、已创建或已找到的记录，以及机场和航线的删除，不提供这个选项。
- **旧版本留下的两步新建**（先新建、再补字段）：新建已应答、补字段请求从未发出时，继续任务会先核对已建的记录，再只补发剩下的步骤，不会重复新建。

### 删除

**机场和航线是软删除**：服务器把记录标为已删除，并没有真正抹掉。对机场和所有类型的航线，只要满足下面两个条件，就显示“API 已核对不可见”，计为核对成功；这不表示数据已被物理删除。

- 删除请求返回了 204，并有回执；
- 随后读取同一 ID 返回 404。

另有两种情况：

- **删除没有回执，但之后读取返回 404**：标为“已删除（无回执）”。这是根据读取得出的结论，和完整证据分开记录。
- **读到 200、缺回执或读取失败**：保持待处理。

机型、飞机和航路是永久删除，照常读回核对。删除前，程序会检查本地引用并刷新依赖，但服务器仍可能拒绝。

任务中心的“API 只读核对删除”可以给结果未知或已人工确认的软删除项补充核对，只发读取请求。具备完整证据时更新为核对成功，并保留原来人工确认的来源；同一任务中待执行的项不会执行。旧任务不会因升级或重连而自动核对或重发。

### 诊断

任务卡片上的“导出诊断”会导出脱敏的 JSON 和 SHA-256 文件，内容包括：

- 完整的字段错误、HTTP 状态和所处阶段；
- 请求时间和服务器时间、追踪头；
- 预期值和实际值的差异。

正文超过 1 MiB 时会明确标记截断，哈希对应完整的脱敏正文。OAuth、Token、Secret、Authorization 和 Cookie 都不会进入诊断包。

## 支持范围与限制

- **单位和格式**：重量单位为 kg，日期和时刻为 UTC。按分钟显示的时刻保留 API 原始的秒数，日期保留原始的小数秒。
- **清空字段**：机场 Container IDs 清空时发送 `[]`，其他未经确认的清空操作都禁用。
- **禁用的操作**：
  - 把航线机队集合清空；
  - 修改 jumpseat 的机队集合；
  - 在 jumpseat 与其他类型之间转换；
  - 给已有机队改绑参数；
  - 写入未经验证的单位和复杂对象。
- **起降机场**：航线和航路的起降机场不能在线修改。
- **到期停用**：是一次独立的 End Date 修改，要满足日期关系校验。
- **新建航线**：所有类型的呼号和班号都必填（jumpseat 留空时自动填入占位值）。成本指数只能为空、AUTO 或 0–999 的整数。
- **复杂对象**：SimBrief 等复杂对象保存在原始数据中，目前没有编辑器。
- **请求量**：所有 VA 合计每分钟最多 60 次请求，并遵守服务器要求的等待时间。列表每页读 100 条，读取 3,000 条航线约需 30 次请求；服务器拒绝这个页长时，自动改用默认的 15 条。
- **没有的功能**：远端事务回滚、删除恢复、团队服务器、自动同步。

## 本地数据

- **数据库位置**：默认在 `%LOCALAPPDATA%/VamSysBatch/workspaces.db`。同一个数据目录只允许运行一个程序实例。
  - 可以在“连接与设置 → 数据存放位置”更改。
  - 设置了环境变量 `VAMSYS_DATA_DIR` 时以它为准，设置页不能更改。
- **更改位置**：
  - 程序先保存，把数据库和备份复制到新位置并校验，成功后切换并自动重启；校验不通过时位置不变。
  - 原位置的数据库改名为 `workspaces-moved-时间.db` 保留，不会再被打开；确认新位置正常后可以自行删除。
  - 选中的文件夹里已有其他文件时，数据放进其中的 `FlightOpsDesk` 子文件夹。
  - 选中的位置已有数据库时，只切换、不复制。那份数据可能较旧，继续远端任务前要先核对。
  - 不能使用网络位置，也不要使用网盘同步的文件夹。
- **找不到所选位置时**：启动时找不到（例如移动硬盘没接上），程序不会新建空数据库，而是让你重试或改用默认位置。
- **先备份，再清理当前工作区**：在设置页使用。
  1. 程序先显示工作区名称、数据目录，以及快照、草稿、任务、冲突和历史的数量。
  2. 确认后冻结操作并等待保存。有执行中、结果未知、可能已发出，或新建后尚未完成核对的记录时，不允许清理。
  3. 程序先用 SQLite 备份整个本地数据库，把完整性检查结果、SHA-256 和清单保存到同一数据目录的 `Backups`。
  4. 备份成功且数据库版本没有变化后，才在一个事务里清除当前工作区的数据、历史、任务和验证标记。

  工作区名称、VA 绑定、连接和时刻设置、凭据密文以及其他工作区都会保留。清理成功后会断开当前连接，需要重新连接并刷新。备份或事务失败时不清理。备份文件包含其他工作区和加密的凭据，请按私有数据保管。
- **升级旧数据库**：先完整备份，再升级，原有的撤销、重做步骤和当前位置都会保留。升级后如果已经发生远端写入，就不能再用升级前的备份继续任务。
- **语言**：在设置页随时切换简体中文和英文，不重建页面，也不重发任务；语言设置对所有工作区生效。官方字段名、用户数据、CSV 和 API 内容不翻译。软件名称在两种语言中都是 **FlightOps Desk**。
- **任务统计**：每次在线任务结束时，程序会把请求量、限流等待、保存统计，以及各项结束时的状态和原因代码写入数据目录的 `performance/<工作区ID>/<任务ID>/<执行ID>.json`。状态和原因代码只按资源和操作计数，不含字段值、ID、凭据或请求内容。

## 大量数据与查重

- **查重依据**：新增航线和航路前，先按机场 ID 查找可能重复的记录。机场、机型和飞机的数据全部读取后，程序会建立查找表，确认写入成功后同步更新。检查飞机注册号是否重复时，会查所有机型。
- **航线的多时段 / 同班号**：vAMSYS 允许同一对机场、同一班号有多条航线（不同时刻、班期或日期）。只有始发、到达、班号都相同，且类型、呼号、起飞时刻、到达时刻、班期、开始日期、结束日期也都相同的新航线，才算重复（“校验”、审阅和在线提交用同一规则）。新航线留空的字段不参与区分，因为服务器可能自动补上（例如开始日期）。某条同班号新航线的提交结果不明时，同一对机场上同班号的其他新航线会等它核对完再提交。
- **结果不明时的查重**：修改结果不明时，查重同时考虑修改前后的名称；删除结果不明时，原记录仍视为可能存在。
- **机场新建尚未核对时**：后续的机场新建会显示“待执行”及原因，其他独立资源照常执行。
