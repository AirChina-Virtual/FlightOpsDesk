# 存储格式 v3 与迁移（2026-09-22）

v3 在 v2 任务拆分基础上，将资源快照与草稿按行保存。在线成功回读只提交目标行；普通草稿保存、刷新、任务初始化和兼容保存仍可以全量写入。完整业务格式 Workspace.Serialize/Deserialize 保持不变。

## 升级与备份

升级前关闭使用同一数据目录的旧版。新版按数据目录持有进程文件锁，同目录第二实例不能打开数据库。默认目录为 %LOCALAPPDATA%/VamSysBatch，可用 VAMSYS_DATA_DIR 指定隔离目录。

旧格式及 v2 均可直接迁移到 v3：

1. 使用 SQLite BackupDatabase 创建 workspaces-before-v3-时间-唯一ID.db，包含 WAL 中已提交数据，并检查 integrity_check。
2. 在一个事务中迁移所有工作区。v2 现有任务表及保存版本保留；旧整块任务拆出。资源写入新表，最后更新 user_version=3。
3. 损坏 JSON、重复稳定行标识或提交前故障全部回滚，不留下部分迁移；应用显示错误，不进入在线执行。
4. 成功后保留备份。重复启动不重复迁移；更高格式拒绝打开。工作区版本触发器拒绝旧版设置 format_version=2 的全量写入，旧三值 INSERT 也不能写入新版表。

只提供迁移前备份，不提供旧格式导出。**升级后发生过远端写入时，不能直接恢复旧备份继续任务。** 备份不包含迁移后的成功或未知状态，必须先核对最新本地记录与远端，不能用它实现远端回滚。

凭据仍由当前 Windows 用户 DPAPI 加密，复制数据库到其他 Windows 用户不能替代重新配置凭据。

## 数据结构

- workspaces：配置、模式及操作验证标记；JSON 不含 Jobs、Resources。
- batch_jobs／batch_items：任务头、顺序及逐条消息、状态、返回 ID、候选历史、期望值和步骤。
- resource_metadata：各资源列定义、冲突 JSON 与快照时间。
- resource_rows：按工作区、资源、Snapshot／Draft、LocalId 寻址，存储行 JSON 与排序序号。
- resource_history：各资源的 Undo／Redo JSON，保持现有撤销语义。
- workspace_revisions：保存版本，拒绝陈旧全量副本覆盖更新后的检查点。
- secrets／app_settings：凭据及应用设置。

草稿更新保留原序号；快照回读保持既有“移除旧条目再追加”语义。删除使用序号空洞，无需重编号其他行。未知 CSV 列、原始 API JSON、旧 Message／Status、候选历史、任务顺序及撤销数据保留。

## 检查点与恢复

Task／Step 检查点仍只保存任务头、当前记录与版本。写请求发送前保存具体步骤及 InFlight 状态；POST ID 保存成功后才能发送补充 PUT。

Rebase 使用独立 ResourceRebaseDelta，包含 Snapshot／Draft 的保持、写入或删除动作。任务成功状态、目标行、快照时间、对应资源撤销清理、验证标记及保存版本在同一个事务内提交。成功后才应用内存变化，并发布携带工作区、任务和记录标识的进度通知。

单项重基线不序列化其他资源、列定义、冲突集合或撤销内容。清理同资源的大撤销历史仍有 SQLite 成本；不承诺物理 WAL 写入字节与数据规模完全无关。旧完整 RebasedWorkspace 检查点作为兼容路径保留，仍可能全量写入，在线应用使用增量路径。

所有保存共用保存顺序和版本检查。关键提交失败停止后续请求，重新读取已提交状态并退出在线；不能读取时保持存储保护。Running／Unknown 恢复只核对，成功项不重发，已有 ID 不重复 POST，补充 PUT 中断不自动补发，软删除规则不变。

## 安全关闭

用户关闭窗口时，先冻结编辑与新操作，再等待排队中的自动保存并保存最终草稿。重复关闭不会再次保存。保存失败保留草稿、恢复交互与自动保存，允许重试；成功才退出。运行任务、模态对话框或交互操作未完成时拒绝本次关闭。

任务页使用虚拟化卡片及详情列表。每次提交只更新对应视图模型与计数，呈现最多合并等待 50 ms；数据库检查点不合并或推迟。视图模型保存已提交显示快照，不读取尚未提交的可变执行状态。

## 验证边界

迁移、WAL 备份、事务故障、真实子进程终止及实际窗口延迟关闭均使用隔离数据库。父测试进程保存模拟远端，覆盖 PUT InFlight 提交前后和远端接受后、响应尚未送达的中断。本轮没有真实 API 实例凭据，不把模拟验证视为真实联调。
