# 旧测试清理：各简报共用的做法

适用于 `C1`–`C7` 各份清理简报。先读 [简报规则与通用约束](README.md) 和 [架构速览](../ARCHITECTURE.md)。

## 目标

`tests/VamSys.Tests`（旧运行器）中的场景，凡是同一行为已被新测试（`tests/VamSys.UnitTests`、`tests/VamSys.IntegrationTests`）覆盖的，就删除；没有覆盖的，先在新项目中补测试再删除。最后旧运行器只保留确实无法迁移或尚未轮到的场景。

## 每个旧场景的处理步骤

1. 读完它的全部断言，列出它验证的每个行为（一句话一条）。
2. 在新测试中找到覆盖每个行为的测试（给出完整测试名）。找不到的，在本简报负责的新测试目录里补写；补写的测试必须先在当前代码上通过。
3. 全部行为都有对应后，删除该场景；文件里的场景全部删除后，删除文件，并去掉 `tests/VamSys.Tests/Program.cs` 中对它的调用。
4. 文件中被其他文件引用的辅助方法或夹具（例如 `StorageScenarios.Fixture()`、`StorageScenarios.Legacy(...)`、`DataUiFixture`）：若仍有引用，保留并移到一个小的共用文件，不要一起删掉。
5. **保留**：`Program.cs` 中的命令行入口（`--seed-*`、`--assert-*`、`--verify-package`、`--verify-qa-package`、各 `--benchmark-*`、`--storage-child`、`--draft-child`、`--export-diagnostic-replay`），窗口脚本和打包依赖它们；以及简报中明确列为保留的场景。

## 约束

- 不修改 `src/` 下任何文件。发现产品缺陷：记录，不修；相关新测试用 `Skip` 并写明原因。
- 每处理完一个文件就运行 `pwsh scripts/check-all.ps1`（快速档）并提交，提交说明：`清理：<文件名> 的旧场景迁移到新测试并删除`。不运行完整档，合并后由主会话运行。
- **不要修改** `docs/TEST-COVERAGE.md` 和 `docs/analyzer-baseline.txt`（多份简报并行，会互相冲突）。覆盖对应关系写进本简报的“结果”一节，主会话合并时统一写入覆盖矩阵、更新基线。
- 旧运行器的场景数在工作树中比主检出少 1（缺 `artifacts/step5-v3-baseline`），属正常；在结果中报告删除前后的数量。
- 任务控制在约 30–60 步以内；做不完时提交已完成的部分，在结果里写明剩余哪些场景。

## 结果格式

```
删除前／后旧运行器场景数：…
已删除场景：<旧场景名> → <覆盖它的新测试名>, …
新增测试：<文件>（<数量>）
保留的场景及原因：…
提交：…
```
