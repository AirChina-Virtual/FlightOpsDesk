# 第八轮：v3 行增量与任务页局部更新（2026-09-22）

本轮在线 API 成功回读使用 ResourceRebaseDelta，不再构造整个资源集合的副本或序列化其他资源。普通草稿、刷新、初始化、演示和完整 RebasedWorkspace 兼容路径仍允许全量保存，不能将它们的成本等同于在线增量重基线。

## 单项重基线

相同任务、目标行及时间，分别加入以下额外数据。每组一次事务，使用触发器记录 resource_rows 的实际变更，断言没有其他行被修改。三份撤销另行覆盖同资源和其他资源。

| 额外行数 | 撤销份数／位置 | 序列化字节 | 耗时 | 托管分配 | 目标行变更 |
|---|---|---:|---:|---:|---:|
| 1 | 0／其他资源 | 1,569 | 10.24 ms | 37,960 B | 2 |
| 20,000 | 0／其他资源 | 1,569 | 1.76 ms | 38,360 B | 2 |
| 20,000 | 3／其他资源 | 1,569 | 1.43 ms | 29,672 B | 2 |
| 20,000 | 3／同资源 | 1,569 | 6.22 ms | 29,672 B | 2 |

本夹具模拟新增成功回读，写入一条 Snapshot 和一条 Draft。已有快照更新沿用移除旧行再追加的顺序语义，SQL 操作次数可能不同，但仍仅针对该 LocalId。第一组包含预热成本，不表示小工作区更慢。

序列化量已不随无关资源和撤销规模增长。清理同资源的大撤销历史仍存在 SQLite 成本；JSON 字节不是物理 WAL 字节。托管分配为 GC.GetTotalAllocatedBytes 累计量，不是峰值内存。上述时间包含序列化与事务，不含真实 HTTP、UI 或业务匹配时间。

# 判重索引修复与性能验证（2026-09-22）

本次承接第五轮性能优化，并修复后续复核确认的缓存生命周期及未知机场别名问题。以下为本地模拟和合成基准，不代表真实 API 联调。

## 当前行为

- 机场、机型、飞机采用执行级远端 ID 字典和签名到 ID 集合的反向索引；机场索引响应中的 ICAO、IATA，机型按名称、飞机按注册号，使用 OrdinalIgnoreCase。同签名多个 ID 全部保留，飞机仍跨全部机型。
- 完整分页读取成功才发布索引；失败后重新读取，不复用部分集合。确认创建、修改和永久删除同步更新索引；确认改名移除旧签名，保留仍使用该签名的其他实体。
- 同批确认结果和未知写入使用独立签名索引。未知修改保留前后签名，未知删除不释放原签名。命中不确定身份的新增保持 Pending，显示待核对原因。
- 机场创建未核对成功时，后续机场创建均保持 Pending，包括已返回 ID 但尚未完成回读的情况。其他独立资源继续执行；输入候选 ID、空列表或核对失败不会解除保护。
- 每次恢复重建未知预留，已成功记录不重发。确认候选重新从 API 读取，不以旧成功任务的本地快照初始化；兼容缺少 RawApiJson 的历史成功记录。
- 航线、航路仍按远端机场对 ID 查询候选，完整分页并本地精确判重。机场删除四路 OR 引用查询、机型依赖筛选保持不变。
- 数据库结构、关键落盘屏障、CSV 格式、API 请求体、限流及能力禁用条件不变。增量保存和任务页局部刷新不在本轮范围。

## 索引基准

合成 20,000 条机型记录，进行 100 次确认改名；每次分别查询原名、新名、已释放旧名及不存在的名称，共 400 次查询。每个返回候选均调用实际 IsDuplicate 精确比较。

| 指标 | 结果 |
|---|---:|
| 完整列表读取 / 成功索引构建 | 1 / 1 |
| 查询次数 | 400 |
| 实际精确比较候选 | 200 |
| 确认改名引发额外列表读取 | 0 |
| 本次构建及查询测量耗时 | 207.1 ms |
| 测量期间托管分配 | 63,055,528 字节 |

构建复杂度与记录数成正比，后续查询只枚举匹配的 ID 集合；不再每次遍历两万行。时间包含首次模拟响应解析、索引构建和循环查询；预制响应生成不计入。分配使用 GC.GetTotalAllocatedBytes，表示累计托管分配，不能解释为峰值或常驻内存。单次本机测量受 JIT、GC 和缓存影响，不作为跨机器性能保证，也不包含真实网络、UI 或 SQLite 写入。

## 请求量与保存基准

已有两万条航线、100 条新增且机场对候选稀疏：判重 GET=100、POST=100、回读 GET=100，共 300 次业务请求；虚拟时间为 299 秒。保留密集机场对的多页测试，不把一次 GET 当作所有 VA 的上限。

SQLite 合成保存仍使用全工作区 JSON；零撤销 / 三份撤销分别为 24,916,345 / 62,289,714 字节，序列化约 187.8 / 300.5 ms，SQLite 保存约 116.4 / 267.4 ms。每组一次。此结果与 API 请求基准独立测量，不能相加作为端到端耗时；JSON 字节不是物理 WAL 写入量。

机器可读结果：`artifacts/index-fix-20260922/benchmark/benchmark.json`。

## 指标与复现

在线任务结束后尝试保存 `performance/<workspace-guid>/<job-guid>/<run-guid>.json`，默认位于 `%LOCALAPPDATA%/VamSysBatch`，也遵循 VAMSYS_DATA_DIR。

- Requests 按资源、执行阶段、HTTP 方法统计；OAuth 单独统计。Retries、Pages 统计实际重试和解析成功的页面。
- Candidates 统计实际精确比较或依赖检查的候选；IndexBuilds 只统计完整建立并发布的判重索引，不把同批确认结果的小型索引计为全量构建。
- RateWaitMs、BackoffMs 统计限流与退避定时等待，不含网络耗时和普通锁排队。
- SaveAttempts、SaveSuccesses、SaveFailures、JsonBytes、SerializationMs、SqliteMs 保留既有口径；性能报告本身不计为业务保存。
- DurationMs、CancellationMs 表示执行时长和取消到退出的延迟。报告不包含凭据、授权头、筛选原值或请求正文；报告输出失败不改变业务结果。
