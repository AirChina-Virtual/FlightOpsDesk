# 综合优化计划（2026-11-08）

重构 R0–R8 已于 2026-11-03 收尾，[审查与优化问题清单](REVIEW-AND-PLAN-2026-10-20.md) 中在重构期间冻结的 E、F、G 系列从本计划起解冻。本计划合并了那份清单中尚未完成的项、2026-11-06 第一次软件真实写入暴露的问题，以及提交后人工确认过多的问题。问题编号（E1、F5、G3 等）沿用原清单，原清单中各项的详细说明仍然有效；执行顺序以本计划为准。

## 目标

1. **提交后少做人工确认。** 只读核对能得出结论的，由程序得出结论。
2. **提交前就拦住会失败的项。** 不再“提交 → 422 → 修改 → 再审阅”反复返工。
3. **审阅不过度保守。** 一个问题只挡住相关的项，而不是整个工作区。
4. **补齐在线适配的验收。** 软件自己的真实写入流程、只在连接后出现的对话框、契约变化的发现。

## 不变的规则

[代码优化计划](OPTIMIZATION-PLAN.md#不能改变的要求) 中“不能改变的要求”和“明确不做的优化”全部继续有效：写入不自动重发，写后回读，限流预算，判重与冲突检查，保存顺序，兼容性。

另加一条：程序自动得出的结论（二次回读、自动找回、无回执删除等），证据中注明来源，不登记为已验证的操作。

## 现状

| 来源 | 问题 |
|---|---|
| 提交后核对 | 回读只读一次，不一致即 Unknown；未知项要等用户点“继续”才核对；读写超时都是 30 秒；无 ID 新建的找回只覆盖 jumpseat（`DuplicateStage` 只为 jumpseat 记录提交前的候选 ID）；回读除日期和数组外要求严格相等；charter、cargo 等航线删除和飞机移动只能人工核对 |
| 提交前预检 | 前缀批准只检查 scheduled 航线（`AirlineParameters.NeedsPreflight`），并在第一个不合格的机队就停下。2026-11-06 两条 repositioning 航线因此被 422 拒了两轮，第三轮才成功（见 [能力矩阵](CAPABILITY-MATRIX.md#软件真实写入记录)） |
| 审阅 | 任何冲突或未决任务都会全局阻止提交；在线模式不运行本地校验；抽样 3 条成功后要手动重新审阅；确认框逐条列出；每次提交都重建审阅清单；只能一次提交全部 |
| 在线适配 | 软件真实写入只有 2026-11-06 的两条航线新建；7 个只在连接后出现的对话框没有窗口测试；契约固定在 2026-10-20，API 变化无法发现 |
| 工程 | 云端 CI 从未运行；任务统计没有按原因记录各项结果，看不出哪种人工确认最多 |
