## jumpseat 留空、审阅摘要与真实验收（2026-11-15）

快速检查通过（单元测试 1,764 项，集成测试 696 项通过、1 项跳过）。新增：jumpseat 新建后 remarks 回读为 null 视为一致（其他值、其他类型仍不一致）；jumpseat 新建留空呼号／班号时请求带占位值；jumpseat 四个不保存的格子留空只读、改类型时清空；校验不再要求 jumpseat 的呼号和班号；审阅项的内容摘要（五类资源，新增／修改／删除，含空字段和 jumpseat）。模拟服务器改为丢弃 jumpseat 新建时的 remarks。

正式包和 QA 包重新生成后，全部 55 个普通窗口用例跑了一轮（5 分 31 秒）：54 个通过，`ToolbarTests` 失败在第一次点列标题后没有排序。QA 包这次记录了窗口收到的指针输入（`input-log`）：点击前后窗口没有收到任何按下或点击，反而在点击的时刻失去了激活（`window Deactivated`）。也就是说这次点击落到了别的窗口上，不是程序丢了点击；怀疑测试取到的列标题矩形为空，点到了屏幕别处，尚未证实。jumpseat 新格子和审阅摘要没有专门的窗口断言。

同日第二轮（新建应答两种形状、同一轮接着执行依赖项、审阅拦住可继续的跳过项、窗口测试点击前先确认位置）：快速检查通过（单元测试 1,769 项，集成测试 709 项通过、1 项跳过）。两个包重新生成后全部 55 个普通窗口用例再跑一轮（5 分 59 秒）：54 个通过，`ToolbarTests` 失败；单独再跑 3 次都失败，失败信息现在是“ID 列标题的矩形为空（元素没有布局）”，等了 20 秒仍为空，此时本窗口在前台。这证实了上面的怀疑：以前点击是落在了空矩形换算出的位置上，不是程序丢了点击；现在驱动拒绝点击，所以由偶发变成每次都失败。表头和数据行在同一个横向滚动区里，整列滚出可见区时列标题就没有位置；测试改为点列标题前先把表格滚回最左，之后 `ToolbarTests` 连续 4 次通过。是哪一步让表格横向滚动没有证实，最可能是测试里把焦点移到第一行（WinUI 把获得焦点的元素滚进视野，而行比窗口宽）；失败信息现在带横向偏移和列标题位置，再出现时可以直接判断。产品代码没有改。

同日第三轮（表头与行对齐、右键可编辑单元格）：表头调整后 `ToolbarTests` 在“行上右键打开记录详情”一步偶发失败（4 次中 2 次）。原因是产品缺陷：可编辑单元格处理指针按下时不区分左右键，右键打开了编辑框，行菜单不出现；只读单元格和单元格之间的空隙不受影响，所以取决于右键落在哪里。修复为只有主键（含触摸、手写笔）开始编辑；测试改为右键第二行的起飞机场格并确认没有打开编辑框。这项修复没有单元测试（没有引用界面项目的测试项目），只由窗口测试覆盖。两个包重新生成后全部 55 个普通窗口用例通过（5 分 32 秒），`ToolbarTests` 另外连续 4 次通过。表头对齐由深色／浅色、舒适／紧凑、中英文的截图核对（截图未保留），没有位置断言；高对比度没有查看。

同日第四轮（在线徽标改为“在线”、可继续的跳过项也挡住刷新和连接设置并显示“继续”、排序按钮跟随语言、单元格按下的判断移到 `CellPress`）：快速检查通过（单元测试 1,786 项，集成测试 710 项通过、1 项跳过）。两个包重新生成后全部 55 个普通窗口用例通过（5 分 38 秒），其中 `LocalizationTests` 新增了排序按钮在两种语言、有无排序时的文字。刷新被挡住的情形没有单独的测试，由共用的判断和修改连接设置的集成测试覆盖。

2026-11-16（刷新拦截的直接测试、依赖项同一轮执行的窗口测试、在线任务的“继续”按钮）：快速检查通过（单元测试 1,795 项，集成测试 713 项通过、1 项跳过）。两个包重新生成后全部 56 个普通窗口用例跑了一轮：55 个通过，新用例 `ConnectedDialogTests.Dependents_of_a_create_settled_at_the_end_of_the_round_run_in_that_round` 失败在自己的断言上（要求运行中卡片从不出现“继续”和“核对未知结果”，而任务运行期间这两个按钮本来就显示）；此前一次失败是测试的种子机型缺货运量，被在线审阅正确拦下。断言改为“运行期间不可点、完成后 5 秒内消失”并记录出现时机后，`ConnectedDialogTests` 13 个用例连续 2 次全部通过。这条用例在真实窗口里走完连接、审阅、确认和任务中心，对象是本机模拟服务器（机型的新建应答读不出 ID）：连接后只有 3 个 POST，任务在这一轮完成并核对，机型的 ID 由自动找回得到。它大约每 100 毫秒抽查一次按钮，更短的瞬间看不到；“依赖项同一轮执行”仍然没有真实服务器证据（见能力矩阵中已说明的限制）。在线任务卡片的按钮文字改为“继续”后没有单独的窗口断言，只有视图模型的单元测试和上面这条用例按新文字查找按钮。

软件真实流程验收（综合优化计划 4.2）于 2026-11-16 UTC 完成，四轮全部成功，记录见 [能力矩阵](CAPABILITY-MATRIX.md#软件真实写入记录)。占位呼号／班号是验收之后加的；同日用户新建并删除了一条留空的 jumpseat（航线 14328149），服务器接受 `CCA000`／`CA000`，新 ID 直接从 `data` 包装的应答读到，记录同见能力矩阵。

## 尚未验证或已知问题


- **需要连接才会出现的 7 个对话框（2026-11-09 已补）。** 现在由 `ConnectedDialogTests` 连接本机模拟服务器覆盖，见上文 4.1。与真实服务器连接时的显示仍要在真实验收（4.2）中查看。
- **单元格首次点击偶尔无效（2026-11-03，原因未查明）。** 全量窗口测试中有一轮 `UiTests.CellEditingTests` 的第一次真实鼠标点击没有打开编辑框，焦点停在标题栏；之前 5 轮和之后 4 轮都没有失败（重试加入后，这 4 轮不再能看出是否又发生）。可能是测试时机，也可能是真实问题，所以测试现在会重复点击，这里留作 R8 人工核对：刚切到窗口后第一次点击单元格，编辑框是否每次都打开。
- **软件真实写入与新界面。** 本轮未执行新的软件真实业务写入，也未做新增界面的窗口视觉验收。独立 API 测试不是软件真实写入验收，见 [能力矩阵](CAPABILITY-MATRIX.md)。已知服务端重量问题仍存在，客户端以兼容策略规避。
- **单元格新外观。** 平时显示文本、编辑时显示输入框的样式，没有人工逐项查看明暗主题和高对比度下的效果。
- **`test-localization-ui.ps1`（2026-10-27 已修复）。** 原来的失败（点击时 Invoke 返回 Unrecognized error）是脚本的时序问题：按钮一时找不到就立即去打开命令栏溢出菜单，而页面这时还没完成布局。现在点击前先等按钮出现，只有确实在溢出菜单中的按钮才打开溢出菜单。另外补上两处脚本落后于界面的地方：恢复删除后需要在预览中确认；审阅页改为整个工作区，每类资源各有 CSV 导出，演示工作区只提供模拟提交。脚本已改为带 BOM 的 UTF-8（PowerShell 5.1 下尚未实测）。在 PowerShell 7 下三段检查全部通过。
- **`scripts/build.ps1`。** 需要 PowerShell 7；在 Windows PowerShell 5.1 下同样因为编码无法解析。
